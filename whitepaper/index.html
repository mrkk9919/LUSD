00Abstract摘要

LUSD 是面向跨境彩票业务的美元计价稳定币。它不做算法调节、不做部分准备金、不承诺任何收益，唯一的价值来源是 1:1 的 USDC 储备。

与常见的"平台积分"不同，LUSD 的定位是钱：可自由转账、可在支持的交易所流通、可随时按 1:1 赎回。平台提供的购彩折扣不以压低 LUSD 价格的方式发放，而是通过一个独立的、不可转让的赠券（LVCH）实现。

这个拆分是本文的核心：把"支付"与"优惠"从同一个资产里拆开，从而在合约层消除"折价买入、平价赎回"的套利路径。

01Background背景：为什么需要另一种稳定币

跨境彩票业务里有三个反复出现的问题：

  • 客户不愿持有波动资产。用 BTC、ETH 计价，客户今天充的钱明天可能少两成，投诉和纠纷几乎无法处理。
  • 跨境结算慢且贵。银行电汇跨时区、跨假期，到账以"天"计，手续费与汇损叠加。
  • 平台需要内部计价单位。票价、奖金、返水都需要一个稳定单位，不能随行情跳动。

为什么不能直接发一枚"打折的稳定币"

最直觉的方案是：LUSD 按 0.98 美元卖给平台客户，赎回时按 1.00 美元兑付，折扣自动落地。这个方案有一个致命问题：

套利是数学问题，不是风控问题。只要"买入价 < 赎回价"且两者都能自由进行，任何人都可以循环操作：0.98 买入 → 1.00 赎回 → 再买入。这个循环不需要买一张彩票，几小时内就能把储备抽干。任何手续费、限频、人工审核都只是减缓速度，不改变结论。

所以折扣必须存在于一个无法被兑换成钱的载体里。这是第 03 节的全部动机。

三种方案对比

方案折扣能否落地能否出平台流通套利风险
平台积分 / 游戏币能不能，只能内部消费无
打折稳定币（0.98 买 / 1.00 赎）能能致命
双代币（本文）能能（仅 LUSD）无

02Design Principles设计原则

以下六条是硬约束。任何与它们冲突的功能需求，都应当被拒绝，而不是通过"临时开关"绕过。

01全额储备

每一枚流通中的 LUSD，背后有且仅有一枚 USDC。不做部分准备金，不做"未来收益"抵押。

02不做算法稳定币

不依靠算法调节供给、不依靠姊妹代币吸收波动。历史上所有纯算法稳定币最终都归零。

03不承诺收益

不支付利息、不做质押生息、不宣传升值。这既是合规要求，也是产品定位。

04折扣与本金物理隔离

优惠只存在于不可转让的赠券中。LUSD 本身永远 1:1，不存在任何折价获取路径。

05角色分离与最小权限

铸造、冻结、暂停由不同角色持有。任何单一角色都无法同时完成"增发 + 转移"。

06冻结有程序

冻结必须可追溯、可申诉、有期限。冻结不是没收，也不阻断收款。

03Dual-Token Model双代币模型

系统由两个资产构成，职责严格分离：LUSD 是钱，LVCH 是券。

维度LUSD（稳定币）LVCH（赠券）
定位支付与结算工具消费折扣凭证
获取方式1 USDC 铸造 1 LUSD购彩时按比例赠送
赎回1:1 赎回 USDC不可赎回
转让自由转账、可上交易所不可转让（合约层强制）

价格恒定 $1.00无市场价格
总量等于储备量，无上限按消费行为增发，用完即销毁

为什么赠券必须不可转让

如果赠券可以转账，客户就能在二级市场以 9 折把它卖给别人——这等于把"2% 折扣"重新变成了"可流通的折价资产"，套利路径又回来了，只是绕了一层。所以不可转让不是产品限制，而是安全边界。

实现方式是在 ERC-20 的 _update 钩子里做拦截：只允许铸造（from == 0）与销毁（to == 0），任何地址之间的转移直接 revert。

// VoucherToken.sol
function _update(address from, address to, uint256 value) internal override {
    require(from == address(0) || to == address(0), "voucher non-transferable");
    super._update(from, to, value);
}
这条限制由合约保证，不依赖前端。即便有人直接调用合约、绕过网页，转账同样会失败。前端只是把这件事说清楚，不是它的执行者。

购彩时的扣款顺序

买票时先扣赠券、再用 LUSD 补足。赠券被销毁（不是转到平台地址），因此不存在"平台囤积赠券再倒卖"的可能。

1

04Reserve & Issuance储备与铸造赎回

LUSD 的价格不是"维持"出来的，是兑换关系定义出来的：合约永远接受 1 USDC 换 1 LUSD，也永远接受 1 LUSD 换 1 USDC。只要这个双向承诺成立，价格就没有偏离的空间。

2

3

Redeem · 赎回
1

调用 redeem指定要赎回的 LUSD 数量

2

3

储备不足时怎么办

这是一个必须提前写清楚的场景。原则只有一条：

宁可停止铸造，不可停止赎回。铸造暂停只影响新资金进入，赎回暂停等于宣告违约。前者是风控动作，后者是信用破产。储备跌破 100% 时，正确顺序是：暂停铸造 → 公布缺口 → 启动补充 → 全程保持赎回开放。

当前原型合约的 pause() 会同时冻结铸造与赎回，这与上述原则不一致，已在第 10 节列为待修复项。

冻结的实现位置

冻结不是靠前端拦截，而是写进 ERC-20 的转账钩子，所有转账路径（含 transferFrom）都会经过它：

// StableToken.sol —— 只拦"转出"，不拦"转入"
function _update(address from, address to, uint256 value) internal override {
    if (from != address(0)) {
        require(!frozen[from], "from frozen");
    }
    super._update(from, to, value);
}

这个写法有一个刻意的取舍：被冻结的地址仍然可以收款。原因很实际——退款、派奖、司法划扣都需要能打进去；如果连转入都拦，平台自己也没法处理。

06Risk Control & Freezing风控与冻结机制

冻结是稳定币绕不开的功能，也是最容易被滥用的功能。我们的处理办法是把冻结拆成两条完全不同的轨道，适用不同程序、不同告知义务。

维度平台风控冻结司法冻结
触发原因异常交易、疑似洗钱、账户被盗、违反平台规则公安、监管、法院的正式文书
谁批准风控负责人 + 合规复核（双人）法务核验文书真实性后执行
是否通知客户立即通知，说明原因类别视文书要求，可能不得告知
客户能否申诉能，7 个工作日内答复向作出决定的机关申诉
期限默认 30 天，续期需重新审批依文书载明期限
是否影响收款不影响不影响

平台风控冻结的流程

  • 触发 — 系统规则命中或人工上报，生成工单编号
  • 复核 — 第二人独立确认，避免单人误操作
  • 执行 — 链上 freeze，同时站内信 + 邮件告知
  • 申诉 — 客户提交材料，7 个工作日内给出结论
  • 解除 — unfreeze，记录操作人与时间

司法冻结的边界

只认正式文书，不认电话与聊天。冒充公检法是高发诈骗手法：对方会要求"配合调查、立即冻结某地址"。正确做法是挂断，通过官方渠道回拨核验，并要求书面文书。任何通过社交软件发来的"冻结指令"一律不执行。

跨境场景还有一个额外约束：不同司法辖区的冻结令效力范围不同，平台应在收到文书后由当地律师判断是否具有执行力，而不是"谁来要都配合"。

冻结不等于没收。被冻结地址的余额依然属于客户，只是暂时不能转出。平台无权划走、无权挪用、无权"充公"。

07Governance治理与权限管理

权限设计的核心问题不是"谁能做什么"，而是"单一主体失控时会发生什么"。目标状态与当前原型差距如下：

项目当前原型主网目标
管理员单一 EOA 地址3/5 多签，成员分属不同法人主体
关键操作延迟无48 小时时间锁，可被观察与拦截
角色分配全部授予部署者铸造 / 冻结 / 暂停三权分属不同多签
合约升级不可升级保持不可升级（见下）
紧急暂停PAUSER 单签即可单签可暂停，但恢复需多签
为什么坚持不可升级。可升级合约意味着管理员可以在某天把"1:1 赎回"改成"0.5:1"，而持币者无法提前阻止。对稳定币而言，不可篡改本身就是信用的一部分。代价是 bug 无法热修——所以主网上线前的审计不能省。

08Compliance合规框架

LUSD 同时落在三个监管框架的交集里，缺一不可：

A博彩牌照

按运营主体所在辖区及客户所在辖区分别申请，跨境投注通常需要双边许可。

B支付 / 汇兑

发行与赎回稳定币可能构成货币传输、电子货币发行或虚拟资产服务，需对应牌照（MSB / EMI / VASP）。

C证券法

不承诺收益、不做分红、不宣传升值，避免被认定为投资合约。这是产品文案的红线。

KYC / AML

  • 铸造与赎回必须经过实名认证，链上转账不强制——这是"入口严、流转宽"的常规做法
  • 大额与异常交易触发来源审查，记录保存不少于当地法定期限
  • 制裁名单与政治公众人物（PEP）筛查，命中即拒绝服务并上报
  • 可疑交易报告（STR）流程与监管报送渠道须提前建立，不能等出事再补

宣传红线

不得出现以下表述："持有即增值"、"年化收益"、"稳赚"、"早买早赚"、"限量发行所以会涨"。
稳定币的价值来自可兑付，不来自稀缺性。任何暗示升值的文案，都会同时招来监管和投诉。

本文档不构成法律意见。具体辖区的牌照要求、储备资产的可持有形式、以及跨境执法协助的程序，均须由当地执业律师出具意见后确定。

以下风险无法通过设计消除，只能被识别、计量与披露。按严重程度排序：

合约风险中代码缺陷可能导致资金锁死或被攻击。原型尚未审计审计、形式化验证关键路径、漏洞赏金
对手方风险中USDC 本身依赖发行方的储备与合规状态，LUSD 继承了这一层风险储备构成披露、发行方分散化
流动性风险中二级市场深度不足时，大额兑换会产生滑点；赎回通道正常时不构成兑付风险做市激励、赎回通道优先级高于交易
冻结误伤低风控规则误判导致正常客户被冻结双人复核、7 日申诉、默认 30 天到期
请特别注意：LUSD 不承诺保本之外的任何回报。持有 LUSD 不会产生利息，也不会因平台业务增长而升值。若你的目的是投资获利，LUSD 不是合适的选择。
